# 小店补货助手
面向表格记账小店的离线补货演示应用。五个页面串联订单质检、库存配置、解释性补货、双策略回放和数据说明。

## 启动
Windows 双击 `启动助手.bat`；首次使用先安装依赖：
```powershell
python -m venv .venv
.venv/Scripts/python -m pip install -r requirements.lock.txt
.venv/Scripts/python -m streamlit run app.py
```
原记录使用 Python 3.14。本轮补充 Python 3.11.4 独立环境验收，实际结果见 docs/验收进度.md；锁定文件的 NumPy 改为兼容该环境的 2.4.6。

## 演示
1. 导入页点击 UCI 真实交易样本，确认完整覆盖日期，点击核验。
2. 库存页修改现货、在途、交期和箱规。库存日期须匹配决策日。
3. 清单页检查人工复核原因、展开计算证据，导出待确认清单。
4. 回放页选择商品、日期及交期，运行并下载实验 ZIP。

## 验证
```powershell
.venv/Scripts/python -m pytest -q
```
策略使用前 28 天连续日均值，保护期 L+1，误差缓冲只采用决策日前已完成窗口。至少 20 个误差样本，最多 60 个，nearest-rank Q90。基线缓冲固定为预测保护期需求的 20%。两者使用相同初始库存、交期和箱规；当日下单在 t+L 日开门前到账。

## 当前交付边界
内置为 UCI Online Retail II 正式数据的20商品样本，5556条真实交易，2010年1—6月。库存参数仍为演示值。尚未完成中国真实商户验证、比赛实践说明及评审录屏。应用是可运行的软件演示版本；不自动执行采购。依赖首次安装需联网，安装后内置样本可离线运行。

## 中文使用指南
左侧「使用指南」提供快速上手、字段字典、计算算例和常见问题。导入页按四步操作；库存配置带中文列名；补货证据和回放指标提供中文解释。CSV库存模板保留机器字段名，以便再次导入。

## 重建 UCI 样本
从官方页面下载ZIP到 data/raw/online-retail-ii.zip，然后运行 `.venv/Scripts/python scripts/prepare_uci.py`。来源、CC BY 4.0署名、筛选口径、训练/测试区间和哈希见 DATA_SOURCES.md 与 data/demo/manifest.json。

只读核验官方ZIP、工作簿和样本逐行一致性：`.venv/Scripts/python scripts/verify_uci.py`。

运行一商品固定配置公开数据回放验收：`.venv/Scripts/python scripts/validate_public_sample.py`，结果在 outputs/validation/；它是软件实验，不代表真实小店经营效果。

## 采购、分批到货与库存风险

先载入销售数据及库存，再在左侧进入「采购与到货」。核对规则建议，填写人工确认数量、采购日期、预计到货日期及确认/修改原因，勾选核实后登记。支持同一商品多笔采购及一笔采购分批到货，累计到货不得超过采购量。

本页有台账时，建议以台账剩余在途替代汇总在途；逾期或超出交期的未到货订单需人工复核。原「补货清单」仍以库存配置为输入，采购台账不会自动改写该历史快照，使用前应复核两者一致性。

风险表按期初盘点、具体到货日期、起始日前28天平均销量计算未来14天期末库存及未满足需求。起始日前的已收货视为已包含在盘点中；自动入库流水对应的到货不会再次加入预测，未入账到货按日期计入；逾期未到部分不假定自动到账。原汇总在途不在风险表重复计入。预测为固定日均情景，不能保证实际需求或到货。

记录按会话隔离，原子保存到忽略目录 `outputs/purchases/`。请下载JSON备份；新会话可在「备份与恢复」中导入，新版完整备份包含采购、库存和流水，恢复时一起替换，不会把历史收货再次入库；商品集合须与当前库存一致。旧版仅台账备份不能用于恢复联动库存。确认收货会自动增加该商品现货、扣减汇总在途（最低为零），同时生成库存流水；每批到货必须填写唯一收货凭证编号，同一凭证重试不会重复入库。到货日期须与当前库存日期一致，跨日需先核对当日销售和盘点。数量变化后实际参数声明重置为待核实。当前没有账号和跨设备数据库，不应依赖公开部署的本机磁盘长期保管经营记录。

## 可选AI助手（千问 / DeepSeek）

不配置Key也能使用全部原有手动流程。服务端设置 `DASHSCOPE_API_KEY` 启用千问，或 `DEEPSEEK_API_KEY` 启用DeepSeek；图片识别仅支持千问。不要把Key写入源码、CSV或GitHub。云环境在环境设置中安全填写；本地通过进程环境变量提供。

默认使用千问中国内地兼容接口 `https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions` 和DeepSeek接口 `https://api.deepseek.com/chat/completions`。保留HTTPS证书校验。其他地区的千问Key不保证可用，不会自动转发到其他地区。可用 `QWEN_MODEL`（默认qwen-plus）、`QWEN_VISION_MODEL`（默认qwen-vl-plus）、`DEEPSEEK_MODEL`（默认deepseek-chat）选择账号已授权模型；模型、额度和实际识别质量须用自己的账号验证。

- 导入与质检 → 智能匹配表头：常见别名在本机匹配；勾选AI后仅发送陌生列名，不发送订单行。结果仍可手动修改。
- 采购与到货 → AI录采购：输入描述，或上传不超过5MB的PNG/JPEG单据。明确同意后才发送描述、图片、候选商品编码和相对日期参考日。图片识别也只产生采购草稿，不能自动登记收货。
- 草稿中的商品、总件数、到货日期均可编辑。箱数×箱规由程序校验；缺失商品或日期须补齐。勾选逐行核对后才批量登记采购，任一行不合法则整批不写入。周五等相对日期请核对参考日及模型解读。
- 补货清单 → AI补货解释与问答：发送所选商品的计算证据及问题，不发送完整销售订单。AI仅解释，不能修改规则结果；回答可能出错，需与展开的计算证据对照。

第三方API按账号计费，只有显式点击生成或解释才调用；失败不自动重试，也不影响手动操作。发送前移除客户、联系电话等隐私。模型输出只作为草稿或纯文本解释，不执行其中代码或指令。

本轮验证覆盖模拟HTTP请求、视觉模型路由、异常输出、数量校验、无Key备用流程及人工确认登记。**尚未用真实Key联调，不代表真实接口权限、当前模型兼容性或识别精度已验证。**

### 每日AI额度

千问与DeepSeek合计每天100次，全站共享，按北京时间日期计数。文字、图片、表头AI和问答统一在发送请求前原子扣减；接口报错或超时也占一次，无Key、输入校验失败、本地别名匹配不扣次数。额度用完后不发送请求，手动功能继续可用。左侧显示已用/剩余额度，页面打开时约每3秒刷新。

计数保存在本机SQLite文件 `outputs/ai_usage.sqlite3`，普通页面刷新或保留磁盘的进程重启不会清零。Streamlit Community Cloud磁盘不是持久数据库：重建、迁移或磁盘丢失可能重置计数；多实例也不会共享本机文件。这是本应用的调用限制，不限制同一Key在其他程序的调用；若需要跨重建严格限额，需要外部持久数据库及服务商账户预算配合。

## 历史数据驱动的模拟经营

先使用首页「用示例立即体验」，再进入左侧「模拟经营」。选择商品、日期、模拟初始库存、交期、箱规及规则，点击「创建或重置模拟」，即可逐日推进或自动运行（页面打开时约每2秒推进一个历史日）。暂停后可查看每天的历史销量、模拟出库、未满足需求、自动模拟采购和分日到货。

- 继续使用已核验的UCI历史交易，或用户导入且确认覆盖的数据；不是实时公开交易接口。默认商品85123A沿用既有固定补充案例，不按策略优劣选品。
- 日内顺序与历史回放一致：当天模拟采购到货 → 以前日及更早销量生成建议 → 导入当天历史销量作为需求代理 → 按可用库存模拟出库。缺货需求不结转，不产生负库存。历史窗口不完整时记录人工复核，跳过当日模拟采购。
- 模拟采购按假设交期自动到货；这不是供应商真实发货确认。期末尚未到期的采购保留在途，不提前入库。取消与退货沿用导入质检口径，未作为真实退货入库自动加库存。
- 页面显示完整逐日记录、采购到货表和库存流水，可下载包含数据指纹、配置、规则版本、逐日决策及汇总的JSON。零需求期间满足率不适用。
- 模拟状态仅在当前会话中保存，离开页面暂停；关闭页面不继续后台经营。数据或商品变化时须重新创建模拟。结果不会写入实际库存或采购台账，也不会调用AI或消耗API额度。
- 历史成交量不含未记录的缺货失销量，初始库存、交期和箱规均是假设；本功能只展示自动化流程，不证明真实门店收益或策略全面优越。

### Community Cloud加载与密钥排查

采购描述默认使用单行输入，避免多行TextArea组件资源加载失败时阻塞录入；需要多行时可勾选切换。如果出现“Failed to fetch dynamically imported module”，先刷新或强制刷新页面，仍失败则在Manage app中重启应用并尝试无痕窗口。它是前端资源加载问题，不是AI返回的鉴权错误。部署依赖固定到本仓库已测试的Streamlit 1.66.1。

推荐Secrets写法如下，放在任何 `[分组]` 之前，替换占位内容后保存并重启应用；不应将真实Key提交到仓库：

```toml
DASHSCOPE_API_KEY = "你的千问Key"
DEEPSEEK_API_KEY = "你的DeepSeekKey"
```

也兼容 `[qwen] api_key`、`[deepseek] api_key`，以及 `[ai]` 中同名的大写键；环境变量优先。页面只报告是否读取到Key，不显示Key内容。读取成功不代表服务商权限、余额或地域已通过验证。
