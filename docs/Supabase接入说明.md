# Supabase持久化接入

本版支持把采购、库存、收货及销售更新流水保存到Supabase，并把千问和DeepSeek每日合计100次的额度交给数据库原子计数。未配置时仍可使用本机存储。已验证本地PostgreSQL 16中的SQL、权限及并发逻辑；这不等于已经连接你的Supabase项目。

## 1. 准备项目地址

登录Supabase控制台，进入项目。在Settings → API / Data API查找Project URL，或在Connect面板查找。格式是 `https://项目编号.supabase.co`，不是控制台浏览器地址，也不是数据库密码。

代码目前支持标准Supabase托管域名，不自动向自定义域名转发密钥。

## 2. 初始化数据库

在项目SQL Editor中新建查询，复制仓库 [database/supabase.sql](../database/supabase.sql) 的全部内容并执行。脚本创建本应用专用的两张表和五个RPC函数，使用事务，不删除现有业务数据；可重复执行。

表启用RLS，撤销匿名和authenticated角色的表访问及函数执行权限，RPC仅向service_role授予执行。不要为了接通应用关闭RLS，或向anon开放写权限。

## 3. 在Streamlit Secrets填写服务端配置

先下载现有采购备份，保留对应的完整销售CSV和覆盖日期。暂停AI调用，并记录当天左侧显示的已用次数，然后在应用Manage app → Settings → Secrets加入以下顶层配置：

```toml
STORAGE_BACKEND = "supabase"
SUPABASE_URL = "https://项目编号.supabase.co"
SUPABASE_SERVICE_ROLE_KEY = "在此填写服务端密钥"
```

密钥使用Supabase提供的服务端secret key（通常以`sb_secret_`开头），或legacy service_role key。不要填publishable/anon key。真实密钥只放在Streamlit Secrets，不发到聊天、不提交GitHub；它会绕过RLS，应仅在服务端使用。

原有DASHSCOPE_API_KEY、DEEPSEEK_API_KEY保留。任何顶层配置都应放在`[分组]`之前。保存并重启应用。

若要保持切换当天已用额度，例如当天已用80次，再加：

```toml
AI_USAGE_MIGRATION_DAY = "2026-11-05" # 改为实际切换日期，北京时间
AI_USAGE_MIGRATION_USED = "80"       # 改为暂停调用时记录的已用次数
```

此配置仅在指定当天生效，数据库取现有值与迁移值的较大者，不会降低已用次数。后续日期正常从0开始。若无法确认旧计数，可把切换日下限设为100以保守停用到北京时间次日零点。不要在记录计数和切换之间继续调用旧后端。

## 4. 验证并恢复

1. 左侧额度应正常显示，不应出现“额度存储不可用”。
2. 在采购与到货 → 备份与恢复点击「测试持久存储连接（不消耗AI额度）」。该按钮读取额度状态，不调用模型，不修改采购数据。
3. 第一次从本机迁移时，先载入备份对应的完整销售文件及相同覆盖日期，再导入采购备份。新建的Supabase工作区会得到新的恢复码。不要把本机旧恢复码误当作已经迁移的云端记录。
4. 旧版备份缺少来源或在途语义标识时，先核对其外部在途是否包含台账采购；排除重复部分后，勾选兼容恢复。否则不要直接应用旧汇总。
5. 保存新的恢复码和JSON备份。新的浏览器会话载入同一销售数据后，输入恢复码即可恢复库存和采购。恢复码相当于本工作区访问凭证，仅本人保管。
6. 两个会话同时编辑时，旧版本写入会被拒绝。先恢复最新记录，再重新核对操作；不要通过重置版本号绕过冲突。

## 5. 失败处理

Supabase配置了一半、密钥失效、SQL未初始化或网络失败时，代码不会静默退回本机建立另一份账。数据库额度扣减未确认时，不会继续请求AI；工作区写入失败时，不先修改会话库存。

如果请求超时，数据库可能已提交而客户端没有收到响应。此时先恢复最新工作区，核对已保存采购或收货凭证，再决定是否重试。相同收货凭证不会再次入库。

需要暂时使用本机模式时显式设置 `STORAGE_BACKEND = "local"`，但这代表使用另一套存储，并不会自动把云端数据复制到本机。切换前先下载完整备份并记录当日额度。

## 当前限制

- 尚未提供账号登录/店铺成员授权；本应用依靠随机工作区恢复码隔离记录，不应公开分享恢复码。多人协作及账号权限是独立的产品需求。
- Supabase项目的备份、计费、暂停及保留期限受其套餐设置影响。定期下载JSON备份仍然必要。
- AI额度限制本应用的调用，不限制同一AI Key在其他程序的使用。建议同时启用服务商的余额和预算提醒。
- 如果在Codex受限环境中联调，需要允许项目域名；Streamlit部署中的Secrets不会自动同步到Codex环境。
