# 参数真实性与多条件验证

本轮解决软件可处理的部分：防止把演示参数误当实际盘点；提供不同假设条件下的完整对比。不能用软件生成真实盘点、补出未记录的失销量，或替代商户经营验证。

## 参数入口

侧栏默认“演示探索”，库存默认标记“演示假设”。“实际采购准备”要求参数性质为实际盘点、有来源说明、已逐项核实；否则数量为空并转人工复核。来源说明必须不同于默认合成演示来源。用户声明不是外部审计，仍须经营者确认。

每次批量导入均将核实状态重置，需在本次会话逐商品确认。保存表单时需再次勾选，避免参数被修改后沿用旧确认。清单附参数性质与结果证据类型；演示清单不能用于直接采购。

## 多条件回放

在“策略回放”底部设置初始库存、交期、箱规，最多8种笛卡尔积组合。每个组合对两种策略使用同样的输入。保留所有条件、缺货、库存、人工复核率及期末在途；零需求满足率留空，不生成效果结论。输入变化会提示旧结果需重跑。

ZIP包含每个条件的指标、差异观察、数据指纹与完整配置，标明“模拟，不是商户实测”。满足率提高同时库存增加会明确标注取舍，不自动评选最佳参数。

命令行复现固定矩阵：

```powershell
.\.venv\Scripts\python.exe scripts\validate_public_sample.py --sku 85123A --matrix
```

输出为outputs/validation/85123A/scenario_metrics.csv、scenario_comparisons.csv及scenario_manifest.json。

## 当前证据

Python 3.11.4下13项测试通过，包括真实参数拦截、矩阵输入限制、双策略同条件以及零需求情况。

已执行UCI商品85123A、2010-05-01至2010-06-30的8种固定组合：初始库存20/100，交期2/7天，箱规1/6件。每组合两策略，共16条指标记录。所有组合均表现为历史误差策略满足率提高、平均库存同时增加：满足率差约4.78—17.73个百分点，平均期末库存差约187.67—212.43件。本结果说明存在库存与缺货取舍，不能宣称全面优越，也不推广到未测试商品或真实店铺。
