| 取消语义错误 | 通用与UCI来源规则分离，可映射可选状态，中文状态归一化，冲突列拒绝 |

| 非法日期落库 | 手工、批量、CSV共用库存校验，先验证/持久化再更新会话，采购页增加坏数据保护 |
| 采购重复提交 | 稳定提交编号、重复内容幂等、成功后清理确认；收货凭证幂等继续保留 |

| 备份商品不一致 | 加入采购—库存交叉校验，以及销售指纹、在途口径和版本检查 |
| 大数与浮点失真 | Decimal精确解析，布尔/非整数/非有限值拒绝，合理数量上限十亿 |

## 其他优化

- 本机原子快照带版本检查，恢复会话不能覆盖其他会话的新写入。
- Supabase服务端RPC保存工作区及每日共享额度，匿名与authenticated角色不能调用；故障时不静默切回本机，也不绕过AI额度。
- 数据库额度使用北京时间服务器日期；支持指定迁移日的已用下限，避免切换当天清零。
- AI草稿绑定输入内容、照片哈希、服务、参考日及数据来源；换输入需重新生成，提交仍需人工核对。
- 商品名称字典支持识别；文字接口连接测试显式计费一次，不发送订单。
- 留出期纯计算缓存，增加固定滚动窗口，保留失败区间；热部署按模块版本顺序刷新。

## 验证证据与边界

测试覆盖核心规则、页面操作、原子写入失败、并发版本冲突、连续销售更新及重复导入、备份与恢复、AI无Key及模拟响应、数据库适配器异常和不回退行为。

专用无网络PostgreSQL 16容器实际执行了初始化SQL：匿名和authenticated访问被拒绝，service_role的RPC可用；120个并发额度请求仅100个成功；过期版本写入失败，工作区可恢复。迁移额度取下限的较大值，不能减少已用，指定其他日期被拒绝。

这不是用户真实Supabase项目联调记录，也不是Streamlit线上浏览器验收。真实项目仍需执行SQL、在服务端安全填入URL与Key后测试。千问/DeepSeek真实调用也取决于部署环境的Key、权限与额度。

多人账号权限、供应商实际到货、真实退款/退货及商户效果均不由这些自动化测试证明。当前没有把未知经营事实交由AI自动入库。

最终完整回归：**140 passed in 50.93s**；`pip check`无依赖冲突，`git diff --check`通过，应用启动、健康接口与首页HTML通过。实际UCI默认留出期仍得到原有对照结果，来源质检为5466条有效、78条取消、12条退货；本机一次选参计算16.87秒，同数据同配置命中缓存0.0026秒，结果一致（单次测量，不代表线上性能承诺）。

专用数据库测试容器和本机HTTP测试进程在验证后已停止清理。真实Supabase URL、服务端密钥及项目SQL初始化尚未在本环境提供，因此不把数据库适配器和SQL的本地通过写成已完成真实项目联调。
